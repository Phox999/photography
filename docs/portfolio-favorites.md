# 作品收藏與預約參考

使用者可在公開作品的每張照片或燈箱點愛心，不需登入，最多收藏 12 張。浮動工具列可檢視、逐張移除或清空收藏，並前往首頁預約表單。

收藏保存在目前瀏覽器的 `phox-portfolio-favorites-v1`，不跨裝置同步。瀏覽器拒絕儲存時，畫面提示只能保留目前頁面的收藏。清除網站資料或結束無痕工作階段可能失去收藏。

表單編輯與送出前確認頁會顯示縮圖；收藏本身可作為拍攝參考，不必額外選主題或填自由描述。其他分頁修改收藏時，確認頁會返回編輯，要求重新確認。成功送出保留收藏供後續瀏覽使用；失敗保留表單內容。

後端從已發布作品清單核對圖片，儲存 `{slug, title, image, number}` 快照。以作品 slug 與圖片路徑辨識同一張照片；排序或名稱調整不改變照片識別。已下架的照片會阻止送出並提示移除。照片連結使用圖片路徑定位，避免重新排序後開錯照片。

後台 `/admin/` 的「參考資料」區顯示使用者收藏的縮圖、作品名稱及照片號碼，可點入該照片。圖片後續下架時顯示說明，保留原申請快照。

## 部署順序

1. 此分支以 `seo-aieo-improvements`（PR #4）為基礎，包含動態作品頁所需的收藏資料。先整合收藏 PR 到該分支，或在 PR #4 合併後調整目標分支。
2. 在現有 Supabase migrations 完成後，套用 `supabase/migrations/202610050002_portfolio_favorites.sql`。
3. 建置並部署：`npm run build:worker`。依現有 Cloudflare 部署設定使用 Worker 靜態資產及 API。
4. 驗收收藏、確認頁、正式提交與後台縮圖。

新增 migration 相容未提供收藏欄位的舊客戶端及舊申請，維持原收件憑證與重試機制，不覆寫 PR #5 的查詢代碼函式。**未套用 migration 前不要部署此功能**，否則帶收藏的提交及後台參考資料查詢會失敗。

## 本機檢查

- `npm test`
- `npm run build:worker`
- `npm run check:seo`
- `npm run dev`，檢查手機／桌面照片收藏、燈箱、重新整理、跨分頁同步與表單確認。

正式 Supabase 與正式後台實際寫入仍需在 migration 套用後驗收；本機使用測試資料不代表已上線。
