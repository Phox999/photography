### 舊合成請求證據的範圍

前次本機合成操作已經對 1、8、100 張移動各送出一次 `PATCH /api/admin/portfolio-changes`，payload 含來源與目的地 upsert、完整 30 組 `order` 與版本欄位；來源含封面時改用剩餘第一張，目的地原封面保持不變，服務端記憶體狀態版本依序增加。這些操作只有本機合成服務資料；當時瀏覽器沒有保存每次原始 HTTP 狀態／完整回應正文，故只視為有限的合成流程證據。真實 Supabase 原子 RPC、復原後保留並行無關編輯、公開快取／頁面順序仍待測。

### 瀏覽器及 Worker 檢查限制

本輪 Chrome 與 IAB 對工作區 loopback 預覽均逾時；isolated `file://` 預覽則被瀏覽器 URL 安全政策拒絕，沒有改以其他方式繞過該限制。已停止本輪啟動的合成及開發伺服器。三個 viewport 截圖、拖曳完整操作、觸控排序、多選／移除焦點、上傳後發布／重載、HTTP 細節仍是待驗證項目。

完整 Worker 嚴格檢查需要目前 source 對應的完整公開資產輸出；受保護的既有 `dist/` 約 16.8 GiB，本輪沒有複製或覆蓋它。不得將隔離輸出的空白 `publicDir` 結果誤報為 Worker 資產通過。

### 本機預覽

一般預覽：

```powershell
npm run dev
```

Vite 不監看 `public/assets/portfolio/`。修改 Astro、CSS、JavaScript 仍由既有 watcher 機制輪詢；新增／替換原始照片後請重啟伺服器並重新載入預覽。建置與 Worker 部署仍需依專案流程處理；本輪沒有部署。
